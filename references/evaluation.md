# 如何判断优化有效

不要为了执行此技能自动启动额外评测。需要评估时，用相同任务、输入、模型、工具和验收条件作前后对照；控制缓存与环境差异，并重复足够次数再讨论稳定收益。

先判断交付正确性与完整性，再比较真实输入/输出token、缓存token、调用次数、耗时和返工次数。工具输出字符数只反映文本体积，不是账单token；外部项目的基准结果不能直接转成本技能的节省承诺。

行为核对示例：

| 情境 | 预期行为 | 不能牺牲的结果 |
|---|---|---|
| 修改指定10页PPT | 复用素材，先验复杂页，局部复核 | 十页完整、可编辑、视觉检查通过 |
| 大型表格计算 | 仅返回摘要，程序读取完整数据 | 全量数据参与计算、口径可核查 |
| 批量API遇到429或401 | 停止同类调用，按原因退避或认证 | 不绕过权限、不伪称取得数据 |
| 长时间构建 | 使用完成事件或合理退避 | 发现失败并保留错误证据 |
| 缺少验证器依赖 | 针对性解决或如实说明限制 | 不把未运行检查记为通过 |
| 已验收的局部修改 | 保存并交付 | 不再扩大范围或新增无必要测试 |

如果更短输出造成漏项或更多返工，即使单次响应token减少，也不算成功。
